# Tea Collection

Личный чайный альбом для Safari на iPhone. Коллекции и фотографии сохраняются в IndexedDB. Сервер приложения, аккаунт и платные API не нужны.

## Запуск на компьютере

Установите Node.js 24, затем из папки проекта выполните:

```sh
npm ci
npm run dev
```

Локальный адрес появится в терминале. Для проверки сборки и офлайн-режима выполните `npm run build`, затем `npm run preview` и откройте напечатанный адрес с путём `/tea-collection/`. Дождитесь установки Service Worker перед отключением сети.

## Публикация на GitHub Pages

1. Создайте на GitHub репозиторий `tea-collection` и загрузите содержимое проекта в ветку `main`, включая скрытую папку `.github` и файл `package-lock.json`.
2. Откройте **Settings → Pages** и выберите **GitHub Actions** в поле **Source**.
3. Откройте **Actions → Publish Tea Collection**. Если запуск ещё не произошёл, нажмите **Run workflow** и выберите ветку `main`.
4. Дождитесь успешного завершения публикации и откройте `https://USERNAME.github.io/tea-collection/`, подставив имя владельца репозитория.

## Установка на iPhone

Откройте опубликованный HTTPS-адрес в Safari. Нажмите **Поделиться → На экран «Домой» → Добавить**. Если Safari показывает переключатель **Открывать как веб-приложение**, оставьте его включённым. Откройте приложение с главного экрана при наличии сети, чтобы интерфейс сохранился для офлайн-доступа.

## Резервная копия

Откройте шестерёнку в верхней части альбома и выберите **Экспорт коллекции**. В меню iPhone выберите **Сохранить в Файлы**. JSON содержит все фотографии, коллекции и записи. Сохраните копию перед сменой устройства, очисткой данных браузера или переносом коллекции из Safari в установленное приложение.

Чтобы восстановить данные, выберите **Импорт коллекции**, откройте файл и подтвердите замену текущего альбома. Локальное хранилище может очищаться системой, поэтому делайте копии после важных изменений.


## Обновление приложения

После публикации новая версия загружается в отдельный кеш. Пока открыт хотя бы один экземпляр предыдущей версии, он продолжает использовать свои ресурсы, в том числе в офлайн-режиме. Чтобы перейти на уже загруженную версию, закройте все вкладки альбома и окно приложения с экрана «Домой», затем откройте альбом снова.

## Фотографии и хранение

Альбом сохраняет фотографии как JPEG с максимальной стороной 1440 пикселей. Для исходных файлов действуют ограничения 40 МиБ и 50 Мп. HEIC и HEIF открываются, если браузер умеет декодировать конкретный файл. При ошибке можно выбрать копию в JPEG или PNG.

Импорт принимает JSON версии 1 размером до 64 МиБ. Альбом проверяет данные и фотографии до запроса подтверждения. При отмене или ошибке сохранения текущая коллекция остаётся в IndexedDB.

Записи и фотографии по-прежнему хранятся одним снимком коллекции. Это позволяет атомарно восстановить альбом и сохранить его совместимость с существующей базой. Структура базы не требует миграции. Каждая запись изменений копирует весь снимок, поэтому при существенном росте коллекций стоит оценить раздельное хранение записей и фотографий по фактическим замерам. Дополнительный ключ с ревизией защищает записи от перезаписи из устаревшей вкладки.

## Автоматизированные проверки

```sh
npm ci
npx playwright install chromium
npm test
```

Тесты собирают приложение и запускают Chromium с мобильным профилем. Локальный HTTP-сервер отдаёт сборку с путём GitHub Pages и имитирует публикацию новой версии. Проверки охватывают фотографии, управление записями, старую базу, импорт и экспорт, откат при ошибке записи, жесты и работу двух версий Service Worker.
